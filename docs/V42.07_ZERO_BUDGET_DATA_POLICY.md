# V43.00 — Market-data policy and authorization gates

## User constraints

- Monthly provider budget: INR 0.
- Intended deployment: personal, non-commercial research only.
- Fundamentals: Screener.in only.
- No Yahoo Finance or Moneycontrol live quote fallback.
- Never fabricate, infer, or relabel missing/stale prices.
- Do not bypass authentication, CAPTCHA, rate limits, access controls or provider terms.

## NSE MCP permission state

NSE MCP is **disabled by default** in the Android build. The Gradle property `enableNseMcpData` defaults to `false`.

Public access to the NSE website does not, by itself, establish authorization to use an MCP endpoint or redistribute its data. Keep the feature disabled unless written permission and the applicable terms for this app's exact use are confirmed. Do not describe the endpoint as an authorized production feed without that evidence.

## Market-data labels

- `EOD`: validated exchange end-of-day data with its actual trading date.
- `DELAYED`: only when a permitted provider explicitly identifies the delay and source timestamp.
- `VERIFIED`: only after the relevant source and payload have been independently validated.
- `STALE`, `PARTIAL`, `UNAVAILABLE`, `NOT_VERIFIED`: use when appropriate.

Do not treat gateway health as proof of upstream market-data health. Do not treat an unofficial public endpoint as an authorized production provider. No synthetic candles, quotes, index values or signals.

## Screener fundamentals

Screener.in remains the sole fundamental-data source. A 401/403 is an access failure, not a reason to bypass controls or substitute values from another provider. An official user-exported Screener CSV may be used as a dated snapshot only, with its export timestamp and source status displayed.

Company-page access, authenticated session status and `/screen/raw/` saved-screen access must be tested separately. A company-page success does not establish saved-screen permission.

## 540-metric reconciliation

The audit is 30 stocks × 18 metrics. It requires an app parser snapshot and a separately obtained authorized Screener export. A self-comparison is not independent verification. Missing reference data must remain `NOT_TESTED`; a template file cannot pass the release gate. Only comparable values with matching units and reporting periods count as verified.

## Release gates

1. All existing saved Screener definitions and device-local overrides are preserved.
2. CI and regression tests pass.
3. Screener access and query execution are tested without bypassing restrictions.
4. The 540-field audit is populated from independent authorized evidence before claiming full verification.
5. Any market-data gateway is authenticated, validated and authorized for its intended use.
6. EOD timestamps, chart calculations and missing-data states are checked on emulator and physical device.
7. Signed production release is withheld until all required authorization, data and signing gates pass.

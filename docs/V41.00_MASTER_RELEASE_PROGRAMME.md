## Non-negotiable engineering rules
1. No fabricated prices, fundamentals, OHLCV candles, corporate events, result dates, dividend amounts, or AI scores.
2. Every displayed data point carries source, source URL or provider identity, reporting period, unit, fetched timestamp, and freshness/quality status where applicable.
3. Screener access must use the user's authorized session/subscription. Never bypass 401/403, CAPTCHA, paywalls, or access controls.
4. No CSV upload workaround for News, Dividend, Results, Board Meetings, Corporate Actions, or Peer Comparison. These modules must use direct authorized sources. Any retained import capability for a distinct user-authorized use case must be clearly isolated and must not silently replace direct provider data.
5. NSE EOD data must never be labelled live. No live quote/candle claims without an authorized real-time feed.
6. One canonical stock data model; one owner for each metric; no duplicate UI cards or divergent calculations.
7. Missing, stale, restricted, malformed, and not-yet-reported values are different states and must remain distinguishable.
8. A code change is not complete until tests and evidence pass. CI green does not prove provider coverage or investment performance.

## Target architecture
Official/authorized providers -> provider adapters -> bounded fetch/retry/cache -> parser -> normalization/validation -> canonical stock/event model -> domain engines -> UI/API.
Domain engines: fundamentals, valuation, technical indicators, query execution, scoring, news/corporate events.
Every provider adapter returns typed status and provenance; a failed provider must not disable unrelated providers.

### WS1 — Canonical data model and fundamentals (P0/P1)
- Define canonical Stock, Metric, Period, ProviderResult and QualityFlag schemas.
- Metric identity includes metric key, value, unit, period, basis (standalone/consolidated), source, fetchedAt, source URL, status and validation method.
- Normalize decimal separators, percent/ratio units, negative values, currency scales, fiscal columns and TTM/annual/quarterly periods.
- Implement duplicate-metric registry and one display owner per metric.
- Screener login/session state must be explicit: disconnected, authenticated, expired, forbidden, rate-limited, parse-failed, partial.
- Validate PE, EPS, Industry PE, ROE, ROCE, debt/equity, PEG, promoter holding and other fields individually.
- Industry PE requires at least three valid comparable peer observations; PEG requires positive, period-consistent growth; Piotroski requires all nine validated inputs.
- Quarterly data target: eight quarters where the source supplies them; financial statements include P&L, balance sheet and cash flow.
- Missing inputs remain unavailable with reason; never coerce to zero.
- Evidence: 30-stock comparison with reference value, app value, source, period, unit, delta and verdict.

### WS2 — Historical data and technical engine (P1)
- Establish authorized NSE historical/EOD source and exact coverage limits.
- Validate OHLCV schema, trading-session ordering, duplicates, gaps, corporate-action adjustments and timezone.
- Implement/test SMA50, SMA200, Wilder RSI14, Nadaraya-Watson envelope and explicit buy/sell rules against deterministic reference fixtures.
- Signal logic must avoid look-ahead bias; backtest with point-in-time data, costs, slippage and survivorship controls.
- No synthetic candles. If fewer than required observations exist, show unavailable.
- Validate fullscreen, landscape, zoom, crosshair, resizing and chart redraw.
- Clearly distinguish custom chart implementation from licensed/actual TradingView integration.

### WS3 — Screener queries, peers and AI scoring (P1)
- Preserve all saved Large/Mid/Small Cap, Hidden Gems and 5% Crash query definitions; version and test exact criteria.
- Query editor supports safe edit, validation, save, execute, history and reproducibility.
- Peer comparison comes from authorized direct data, not a CSV upload fallback.
- Score only validated inputs. Show coverage, factor contributions, penalties, confidence and missing-input count.
- Insufficient coverage must suppress numeric scores/recommendations.
- AI narrative must cite the actual app data used and separate fact, calculation, inference and risk.
- Backtest any strategy claims point-in-time and survivorship-aware.

### WS4 — News, dividends and corporate events (P1)
- Use direct official NSE/BSE announcements, corporate action, board meeting and financial-results sources where publicly/legally accessible.
- Parse original filing links and fetch filing details only from allowed official hosts.
- Map symbols/company names using a verified security master/alias table; do not fuzzy-match ambiguously.
- Deduplicate by exchange + filing identifier/link + normalized title/date.
- Extract dividend amount/type/ex-date/record date only when explicitly present in verified filing.
- Distinguish announcement timestamp, scheduled meeting/result date, ex-date and record date.
- Distinguish results announcement from actual quarterly financial statement.
- No CSV upload UI or CSV fallback for News, Dividend, Results, Peers or Corporate Events.
- If feeds are blocked/incomplete, show provider status and official filing navigation; do not claim full coverage.

### WS5 — Reliability, security, UX and device QA (P2)
- Provider-specific connect/read timeouts, bounded retries with backoff, cache TTL, stale-data state and circuit-breaker behaviour.
- Redirect/host allowlists, response-size limits, XML/HTML parser hardening, HTTPS-only filing links.
- No secrets in APK, source, logs or client-side JS. Screener session cookies must remain protected and never be logged.
- Add accessibility, responsive layouts, loading/empty/error states and source/period labels.
- Run Android emulator and at least one physical-device install/launch/navigation/data-refresh/chart test.
- Capture logcat and UI screenshots for failures; redact session data.
